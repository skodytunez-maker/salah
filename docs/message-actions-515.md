# Personal and team message actions

This candidate adds Reply, Copy and deletion to the existing staff messenger. It does not open staff conversations to ordinary accounts or change support tickets.

Each participant may delete a message for themselves. This is a private server-side hide attached to the account, retained across reloads and devices. Only the original sender may delete their own message for everyone. The existing current-session, confirmed-account, staff-role, MFA and direct-room membership checks apply to both operations; even the owner cannot act in another person's direct conversation.

Global deletion replaces the message with the existing tombstone, empties its stored body and reply reference, and stops new attachment signing. Hides/redactions are excluded from applicable inbox previews, unread counts and queued push candidates. The existing five-minute signed URLs and previously downloaded files cannot be recalled from recipients' devices. Physical storage deletion is not claimed by this candidate.

Reply targets must still be visible to the sender and belong to the same room. Quotes are generated from the target's current visibility at read time. A hidden or globally deleted source returns only an unavailable marker, with no original author, body or attachment URL. If the target becomes unavailable before sending, the composer keeps text/files, clears the reply selection, and waits for another explicit send action.

A visible quote is a keyboard-accessible source button. It scrolls to, focuses and briefly highlights an already-loaded visible message in the same conversation. Reduced motion uses an immediate scroll. A source outside the loaded pages produces a localized load-earlier notice; it does not change the URL, fetch data or paginate automatically. Unavailable quotes stay noninteractive. Each cabinet request captures its current actor before asynchronous session lookup; the transport aborts before fetching if the resolved account differs.

The conversation-header menu also deletes prior history for the current account or, where permitted, for everyone. Any current participant may clear their private conversation for everyone; clearing the shared team history for everyone is owner-only. These whole-conversation permissions are distinct from author-only deletion of an individual message. Both choices require confirmation and keep unsent text/files. A cleared direct conversation leaves the inbox until a future visible message arrives; opening the contact does not restore prior history. The shared team keeps its fixed address with empty history so members can write again; clearing it does not leave the team.

History boundaries use an internal database message sequence, so new messages remain visible even when timestamps share a clock tick. Each whole-clear operation has an account-bound idempotency UUID; replaying an old operation cannot erase later messages or change another room/scope. Per-account history cutoffs and global clear revisions also apply to quotes, reply targets, attachments, unread counts and push candidates.

The message button is keyboard accessible. Touch long-press opens the same native dialog; pointer movement, scrolling, cancellation and hidden-document events cancel the pending gesture. The dialog has functional actions only, native modal focus containment, Escape dismissal and focus return. Text and names remain user content and are not translated.

A per-room global privacy revision, a per-account history revision and a per-account/room hide count form the visibility version. An account's marker exposes no other account's hide sequence. Version changes invalidate both cached page groups and the rendered history before an asynchronous replacement request; failure shows a localized error/retry without retaining known-hidden text, quotes or links. Pre-delete in-flight reads are rejected by the local generation guard. The composer remains mounted, with its draft and selection intact. Peers see changes through the existing eight-second foreground poll; no realtime or immediate remote-device delivery is promised.

Deletion changes the visible history only after a validated server acknowledgement. Network errors do not produce an optimistic success. Repeated operations are idempotent, and new hide/redaction mutations are limited to sixty per account per minute. Existing downloaded copies and offline clients are outside an immediate recall guarantee.

Server cutoffs also suppress fresh reads and signing for older clients. An already-open pre515 client may retain an older page it cached before the change until remount/update, because it does not understand the new visibility version. This candidate does not force an update or claim remote recall of that cached copy. Whole-conversation operations have their own thirty-per-minute limit.

Deploy the CLI-created migration `20261118084403_staff_message_deletion.sql` and the matching staff-cabinet Edge handler before distributing the updated client. This document and local fixture checks do not apply the migration, deploy a function, delete real messages or authorize publication.

Validation: `scripts/check-staff-message-deletion.mjs` exercises actual isolated PostgreSQL and HTTP permissions; `scripts/check-staff-message-actions.mjs` and `scripts/check-staff-conversation-actions.mjs` mount the actual messenger for eight-language actions, replies, clipboard, keyboard/touch, stale reads, failures, account transitions and whole-history cutoffs. The default support bubble retains a known514 markup golden; new actions and layout are messenger-only. Existing staff SQL, DOM, language and endpoint regressions remain required.
