# Private learning cabinets and homework

421 connects the prepared 417 teacher and invited-student cabinets to the existing classroom-schedule API, on top of published 420. The owner appoints confirmed registered accounts by nickname. Teacher access is checked against the private role table on each protected request; owner operations also require the existing MFA gate. Student lessons are selected only through that account's enrollment. The three public experimental Knowledge cards remain disabled.

Optional homework supports up to 2,000 text characters, one audio recording/file and five JPEG/PNG/WebP photos, each up to 6 MiB. Recording requires an explicit microphone action and ends at three minutes. The teacher accepts or returns work with feedback. Re-submission clears the previous review; versions and homework revisions prevent stale overwrites. Optional 10/15-item Arabic reading homework retains a frozen prompt snapshot and manual teacher marks.

Private homework tables have RLS and no direct anon/authenticated grants. The private bucket has a restrictive browser-deny policy. The verified server issues non-upsert upload links and five-minute read links, validates file ownership, byte signatures, size and lesson access, and applies per-account upload limits. Pending orphan cleanup is bounded and never removes submitted files. Signed links and work are not stored in the public service-worker cache.

Account links appear only for teachers or enrolled students. Unsaved forms and recordings block automatic updates and warn before navigation. The learning interface is loaded on demand, shares one pending import and offers retry on failure; navigation cancels stale rendering. Ordinary browsing does not load the video SDK. The existing private video gateway now checks appointed teachers as well as the owner, scopes rooms to their creator, and rechecks/revokes teacher access.

Validation includes isolated PostgreSQL enrollment/permission/version/storage-policy checks, actual cabinet controllers and the full student/teacher review flow. Production schema grants, bucket settings, CORS and anonymous/session rejection are checked separately. Physical phone microphone capture, real account uploads and end-to-end room participation still need device acceptance; automated fixtures do not claim those results. Existing lesson notification delivery/platform limits are unchanged.

The private gateway requires its host computer and Tailscale connection to remain running. Before any restart, obtain a fresh authenticated LiveKit check with zero rooms and participants. Rollback must keep classroom records and the private bucket; restore the previous handler/gateway source and issue any client rollback under a higher build number. Do not open the public learning gates as a rollback or deployment step.
