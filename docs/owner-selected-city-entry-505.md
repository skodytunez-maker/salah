# Selected prayer city on app entry

Release 505 includes the already selected prayer city in the existing app-state report on entry, resume, settings changes and its normal heartbeat. A guest on Home can therefore supply the same selected-city context without starting listening, Quran reading or dhikr. No extra location request, GPS permission, IP lookup or default city is introduced. A missing saved city is explicit `null`; the client never fills it from an account nickname, a historical guest claim or device coordinates.

The shared `guestSelectedContext` helper copies only the bounded city name and optional country from current saved prayer settings. Coordinates and time zone are not included. The reporter includes this pair in its existing bounded state signature. Guest/account identity is captured per packet, and the bridge checks identity, authenticated session and the current saved city again before sending after an asynchronous session read. Changed context is retried through the existing bounded coalescing/retry path, rather than sending a superseded city. Auth changes, privacy revocation and disposal retain their previous cancellation behavior.

The optional packet field is `selectedCity: null | {city, country}`. Omission remains compatible with older clients and preserves their prior server context; explicit null clears it. The owner-only response provides `selectedCity: null | {city, country, reportedAt}` after existing active-session and MFA verification. Backend selection is clear-aware and does not join a claimed account's city into its former guest's actor. Backend retention, timestamps and response filtering are covered by the companion SQL tests; this client patch does not write any other account/guest ledger or credit state.

The private Current Activity card shows a conditional “Prayer city” row when a valid context exists. It hides an absent or malformed city row instead of displaying “No data”. Player and Top-credit unknown states keep their honest existing labels. Names are escaped as source text with automatic direction; interface language changes translate the label without translating a selected city or country. The view retains its existing visible-only polling, cancellation and immediate clearing on loss of owner access.

Coverage: `scripts/check-app-state.mjs` exercises actual guest Home entry, account entry, settings clearing/change, resume, delayed-session city changes, account transitions, consent and packet exclusions. `scripts/check-owner-current-activity.mjs` covers conditional city rows, hostile/oversized/future/coordinate-bearing context, all eight interface languages, unchanged source names, access lifecycle and the separate player/credit expiry rules. Tests use fixtures only and perform no production requests.
