# Android web updates
The Android APK keeps its local origin and bundled offline assets. SalahLiveUpdate checks only the fixed HTTPS SALAH Pages endpoint every five minutes on foreground resume. It downloads an immutable SHA-256-addressed ZIP, rejects redirects, foreign hosts, oversized archives, path traversal, duplicates and native code. Network or storage failure leaves the working app intact.
Downloads are staged atomically and applied on the next Activity creation, never during Quran playback. The application acknowledges its exact web version after the app module boots. If it fails to boot within 30 seconds, or the process dies before acknowledgement, the next launch rolls back to the last confirmed release or APK assets. User data, sessions, downloads and widgets remain on the same local origin; no app uninstall or storage clearing occurs. Android dependency notices come from the installed APK.
Pages publishes the manifest and ZIP on each deployment; its ZIP is built from the same native-entry and pinned Capacitor runtime as the APK. Current native interface schema is 1 and minimum binary version is 332. Increase minNativeVersion when a web release requires a changed native interface. Native plugin/permission changes need a new signed APK or Play update.
The existing APK signing certificate has not been recovered. A newly built debug APK is for testing and must not be represented as a compatible in-place update of older installations without comparing certificate fingerprints. Google Play closed-testing participation still requires installing through the Play test invitation; a sideloaded APK does not count.
