# Owner current app state

Release 500 adds «Активность сейчас» to the owner workspace. Existing «Посещения» charts, user profiles and the three anonymous public activity counters keep their purposes. This is an owner feature; the public announcement remains 499.

The existing owner-access handler serves GET `?mode=app-state&page=N` only after verifying the owner with Auth, the signed claims and issuer, an active session and AAL2 with a verified TOTP factor. It remains `no-store, private`. The read module is `supabase/functions/owner-access/app-state.mjs`; it performs SELECT queries only and never enrolls guests or creates aliases. No new table or report is publicly readable. The client-side owner grant only controls display; it never replaces the server checks.

The response contains `updatedAt`, `freshForSeconds:45`, `total`, `page`, `pageSize:50` and at most 50 `items`. Each item has an owner-only identifier, guest flag and display name, an allowlisted section, player state, its own `playerSignalAt` and `playerExpiresAt`, optional Top-credit pause, last signal and last action timestamps, a visibility flag and optional application version. No section URL, message contents, text of clicked controls, coordinates, selected city, country or movement history belongs to this report. Qibla location remains on the device and is not part of the state packet or owner read. Existing selected-city reporting stays in its separate owner-only feature.

Sections are home, knowledge, quran, reciters, qibla, adhkar, more, settings, account, support, staff, lesson, radio, admin and other. Player states are playing, paused, stopped and unknown. Unknown or expired playback is displayed as «Нет данных», never inferred to be paused/stopped or asleep. Last action time is approximate server receive time minus the reported age of a trusted action; a signal is not an action, and neither proves attention or reading.

For each actor the read prefers the latest visible fresh app-state tab for its section, while any fresh playing tab with a current account session can report playing. Playing expires 45 seconds after that actual playing source's timestamp; a newer paused-tab or general heartbeat cannot extend it. Without a playing source, only a fresh explicit modern player report supplies paused/stopped/unknown. The UI expires player state with its separate deadline using monotonic elapsed time and the server timestamp. General signals older than 45 seconds get «Нет свежих данных», while a still-fresh general signal can coexist with unknown expired playback. Last section is retained as a past observation. Guest manual credit holds override the client credit field, but do not change player state. Fresh explicit modern credit/version reports take precedence over coarse legacy fields. Account and guest activity remains separate from Top-eligible seconds.

Clients predating 500 remain visible through bounded last-24-hour app presence and existing account/guest activity. Only an older or identical legacy observation for the same actor and tab is superseded by a modern report. A fresh legacy device is retained beside an actor's older modern device, and the actor still appears once. Fresh modern foreground section reports take precedence over coarse legacy heartbeats. Legacy last-action timestamps stay null. A fresh genuine old playing report is usable; an old false listener report is unknown and cannot prove pause or stop. Reading/dhikr kinds supply only their known coarse section. Unverified/anonymous/banned accounts do not appear; expired account sessions cannot claim fresh playback. Guest names come from the existing unclaimed ledger alias or «Гость», without rendering raw IDs or linking guests to account cards.

The owner UI keeps data only in memory, refreshes approximately every 15 seconds while this view is visible and authorized, and supports explicit refresh/pagination. It cancels pending work and clears names on navigation, disposal or loss of access. A late response cannot restore cleared private data. Network failures retain explicitly labelled last signals, which continue to expire locally using the server timestamp. Actual delivery remains subject to platform suspension and connectivity; absence of a signal is not proof that audio stopped.

The new private table stores the last state per actor/tab and has 24-hour cleanup. It is not a click/event log. Tests apply the actual migration in isolated PGlite and use mocked owner/auth/network/DOM paths; they do not read or change production accounts, send notifications or run device audio.
