# SALAH

Мобильное web/PWA-приложение. Публикуемые файлы находятся в dist.

## GitHub Pages

В Settings → Pages выбрать GitHub Actions. Публикация запускается после загрузки изменений в main; вручную — Actions → Publish SALAH → Run workflow. Общая ссылка появляется в успешном запуске и в Settings → Pages. Только содержимое dist публикуется как сайт.

Проверка перед загрузкой: node scripts/check-pages.mjs. Дополнительная сборка и установка пакетов не требуются.

## Перенос личных данных

На каждом телефоне сначала открыть старую ссылку SALAH → личный раздел → Настройки → Экспортировать данные. После публикации открыть новый адрес в Safari и восстановить сохранённую копию через Настройки → Восстановить из копии. Затем добавить новый адрес на экран Домой. Данные хранятся отдельно для каждого адреса и сами между ними не переходят. Старый значок можно оставить до проверки нового.

## Обновления

Публичное «Что нового» содержит только новые функции и разделы для пользователей, короткими фразами. Внутренние настройки, технические исправления, обслуживание и изменения кабинета владельца описываются в Git/PR, но не в `APP_CHANGES`, `APP_ANNOUNCEMENT` и публичных уведомлениях. Обычные исправления выходят тихо; всплывающее объявление меняется только для крупных пользовательских новинок и показывается один раз. Метаданные в `dist/js/app-release.js` и `dist/sw.js` должны совпадать.

Готовая скачанная версия применяется при следующем запуске. Новая версия во время чтения ожидает следующего запуска либо кнопки Обновить. Ручная проверка: Настройки → Установка SALAH → Проверить обновления. При изменениях файлов dist нужно менять номер salah-shell-v в dist/sw.js; это включает обновление офлайн-оболочки.

## Происхождение

Копия подготовлена из сохранённой версии c005505b2317d6949619542a52458123504445cf. Для GitHub Pages изменены относительный id PWA и номер оболочки (v56). Сведения об источниках текстов и аудио находятся в dist/data; лицензии шрифта и магнитной модели сохранены в dist/assets.

Публикация не добавляет сервер для фонового Азана или синхронизации данных между устройствами.

Владелец видит на главной компактную карточку каждой установленной версии после серверной проверки доступа и MFA. Закрытие сохраняется отдельно от публичных объявлений и отдельно для аккаунта; обычные пользователи не получают дополнительные всплывающие уведомления.
